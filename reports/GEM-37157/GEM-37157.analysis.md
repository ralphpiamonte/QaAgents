Issue: GEM-37157 (Story)

1. Jira issue summary
3.1 FE - Catalog Import - Spectacle Lens Success/Failure Toast and Post-Import Visibility

2. Requirement/bug analysis
- Story scope is FE behavior after user clicks Confirm on Spectacle Lens import confirmation popup: in-progress, success, and failure toast behavior plus post-import visibility in Catalog.
- Success toast requirement: green toast with exact message "Spectacle Lens imported successfully", includes dismiss control (x), and follows existing Frame import toast position/styling/duration.
- Failure toast requirement: red toast with exact message "Spectacle Lens catalog import failed.", includes dismiss control (x), and follows existing Frame import toast position/styling/duration.
- Loading-state toast requirement: yellow in-progress toast while import is running, includes dismiss control (x), and follows Frame import toast pattern.
- During import-in-progress, user cannot import new items: checkboxes and Select All are disabled until completion.
- After successful import, imported Spectacle Lens records must be visible under Settings > Ordering > Catalog > Spectacle Lens.
- In catalog import section after successful import, imported records are greyed out, non-selectable, and remain with checkbox selected.
- When user filters/searches by Product Category = Spectacle Lens, imported records appear in Catalog tab results table.
- Catalog table behavior for Spectacle Lens references GEM-35700; this story depends on that behavior being implemented/defined.
- Description includes pricing/status/marketability/invoice rules that appear largely BE/data-rule oriented; FE verification should validate visible outcomes where exposed in UI, while rule computation likely depends on BE story GEM-35253.

4. Ambiguities

- Requirement says imported records in import section are greyed out and checkbox selected; unclear whether this applies immediately after success only or persistently for all previously imported items.
- Unclear whether user can navigate away during in-progress import and whether disabled state persists across navigation/refresh.
- Unclear expected behavior when multiple imports are initiated in sequence after first completion (toast stacking/queuing).
- Unclear if failure should keep records selectable for retry in import section and with what checkbox state.

5. Risks
- FE/BE contract mismatch could show incorrect toast state (e.g., success shown on partial or failed backend processing).
- Disabled-state race condition may allow duplicate import submissions if controls are not atomically disabled.
- Incorrect category filter mapping may prevent newly imported Spectacle Lens from appearing in Catalog tab.
- Styling/pattern drift risk if Frame import toast pattern changed and this feature does not inherit same component.
- Greyed-out/non-selectable state could be applied to wrong rows if row identity mapping is unstable.
- If catalog refresh is delayed, users may perceive import failure despite backend success.
