Issue: GEM-32064 (Story)

1. Jira issue summary
LC-01 - Professional services - catalog upload- List screen(search results)

2. Requirement/bug analysis
- Story scope is for Professional Services catalog list/search behavior, with Lens Crafters-specific additions that are visible for all organizations.
- A UPC search filter must exist for Professional Services with input constraints: numeric characters only, min length 0, max length 200.
- UPC search supports partial search; example indicates entering "321" returns UPCs that start with and contain "321".
- If UPC filter is empty, no UPC filtering is applied.
- Product list must include a UPC column as second column after Description.
- Description field must be a hyperlink opening PDP.
- Initial list source: Professional Services retrieved via API for a specific organization by mapping location store number to organization.
- Catalog updates follow existing PV model: updates occur only when source systems (SAP/Eclipse) change, not from VisionX catalog modifications.
- Price must update whenever a new price is received by API.
- User can update price in VisionX even if this causes misalignment with external price.
- Visible table price must be the currently valid price.
- No ability to add custom products in VisionX for this catalog.
- Any behavior not explicitly changed remains as current implementation (edit table behavior, visible data, extension management).
- Linked bugs indicate prior/related risk areas: UPC column visibility, UPC search functionality, filter layout, location-specific price leakage across locations.

3. Missing information
- Definition of "currently valid" price is not explicitly specified (API latest timestamp vs effective date vs VisionX override precedence).
- Exact matching semantics for partial UPC search are unclear (contains only, starts with only, both with OR/AND, exact prioritization).
- Expected behavior for UPC inputs with leading/trailing spaces is not specified.
- Expected behavior when non-numeric characters are entered is not specified (blocked typing, sanitized, inline error, server validation).
- Whether 200-character max is client-side only, server-side only, or both is not specified.
- Expected sorting/default order of list/search results is not specified.
- Pagination behavior and performance expectations for UPC search are not provided.
- PDP destination details are referenced externally and not included in this issue context.
- Authorization/role constraints for who can update price in VisionX are not provided.
- Conflict-resolution rule when VisionX price update and API price update occur close in time is not specified.
- Expected behavior for duplicate UPC values across different services is not specified.
- Error handling requirements for API failures/timeouts in catalog retrieval are not specified.

4. Ambiguities
- "start with and contain '321'" is logically ambiguous and may be interpreted as startsWith OR contains.
- "visible for all other organizations" may imply global rollout, but story context is Lens Crafters-specific additions; rollout scope/timing unclear.
- "No filters are applied" when UPC empty could still include other active filters; interaction rules with other filters are not stated.
- "No possibility to add custom products" does not clarify if existing custom products (if any) should be hidden, retained read-only, or unaffected.
- "Catalog update managed as PV" references another implementation not detailed here, creating interpretation dependency.
- Description hyperlink behavior does not specify opening same tab vs new tab.

5. Risks
- Regression risk that UPC column is not rendered or appears in incorrect position (linked bug GEM-33848).
- Regression risk that UPC search is non-functional or mismatched with expected partial logic (linked bug GEM-33849).
- UI risk for filter layout and responsive behavior (linked bug GEM-33870).
- Data isolation risk where price updates from one location bleed into other locations (linked bug GEM-34133).
- Data consistency risk between VisionX manual price updates and incoming API prices leading to unexpected overwrite behavior.
- Validation risk if numeric-only and max length constraints are inconsistently enforced across client/server.
- Integration risk in store-number-to-organization mapping causing wrong catalog content.
- Usability risk if large UPC inputs (up to 200 chars) degrade search performance.

6. Dependencies
- SAP/Eclipse source systems for catalog and pricing data.
- Catalog retrieval API that maps location store number to organization and returns professional services.
- VisionX catalog UI components for filters, table column rendering, and hyperlink behavior.
- PDP routing/navigation implementation referenced by description hyperlink.
- Existing PV catalog update mechanism behavior.
- Organization/location context resolution in session or request context.
- Permissions model for price edit capability in VisionX.

7. Clarification questions
- For UPC partial search, should match logic be contains, startsWith, or both? If both, is it OR logic?
- How should the UI handle non-numeric UPC input: prevent typing, strip characters, or show validation error?
- Should pasted input containing non-numeric characters be rejected or sanitized? What exact message should be shown?
- Should leading/trailing spaces in UPC input be trimmed automatically before search?
- Is max length 200 enforced both client-side and server-side, and what is expected error behavior when exceeded?
- What is the precedence for displayed/valid price when both VisionX manual update and newer API price exist?
- Does "currently valid" price depend on effective date ranges, and if so, what date/timezone rules apply?
- Should description hyperlink open PDP in same tab or new tab?
- If UPC filter is empty while other filters are active, should only UPC be ignored and others still applied?
- Are duplicate UPCs across multiple services allowed, and if yes, should all matching rows be returned?
- What is expected behavior when catalog API is unavailable (error message, retry, cached data, empty state)?
- Are all organizations intended to receive this UPC filter/column now, or only LC with a later rollout?
