Issue: GEM-35732 (Story)

1. Jira issue summary
5. BE - Catalog Import - Spectacle Lens Add-Ons Search Results, Selection, Add Confirmation, and Toast

2. Requirement/bug analysis
- Scope is Story behavior for Catalog Import when Product Category = Spectacle Lens - Add-Ons, specifically search result display, selection mechanics, pagination interaction, add confirmation, import-state gating, toast outcomes, and default imported record attributes.
- Search Results table must show columns: Checkbox, Category, Product Name. Billing Code was explicitly removed from requirements via comments.
- At initial load for this category, table should show all available results (matching existing Catalog Import pattern). If no data, empty state text must be exactly: "There is no data to display".
- Duplicate rows must not be shown. Uniqueness is based on VW code; if same add-on arrives from multiple sources, only one row appears.
- Rows for already imported add-ons remain visible but disabled/greyed out, cannot be selected, and are excluded from header checkbox select-all behavior.
- Header checkbox behavior is page-scoped to selectable visible rows only: empty/partial click selects all selectable visible rows; checked click deselects visible selected rows; reflects unchecked/partial/checked states correctly.
- Row-level checkbox selection controls selected count near Add button, and disabled rows cannot be selected.
- Selection lifecycle: new search clears current selection; selection is not retained across pages (explicitly reinforced by comments removing persistence requirement).
- If user has current-page selections and attempts pagination, a confirmation pop-up appears (existing behavior pattern): confirm clears current-page selections and navigates; cancel keeps user on current page with selections preserved.
- Pagination must follow existing pattern: default page size 10, options 10/20/30, range and total shown, navigation controls shown.
- Footer actions: Select all in footer shown and clickable when table has at least one item; Add button disabled until at least one selectable row is selected; selected count shown near Add.
- Add flow: clicking Add with selection opens confirmation pop-up with exact message containing selected count and actions Cancel/Confirm. Cancel preserves selection and closes modal; Confirm starts import for selected records.
- Toast behavior after confirm import: yellow in-progress toast during loading; green success toast with exact success text; red failure toast with exact failure text. All toasts include dismiss (x) and match existing Frame import toast position/style/duration.
- During import loading, user cannot import new items (checkboxes and Select All disabled).
- On successful import, imported records are created with Status = Active and Price = Open Price.
- Post-import visibility expectation in this story text indicates imported rows appear greyed out/disabled in import page and records are visible in Catalog tab; detailed catalog tab behavior is out-of-scope and covered by GEM-35733/linked catalog stories.
- Story is BE-labeled but links indicate FE implementation stories exist; end-to-end validation should verify API responses support UI states (disabled, deduped, import result).

4. Ambiguities
- "Select all" appears in footer and says it selects full list of available results, while header checkbox is page-visible-scope; interaction precedence and resulting selected count behavior across pages can be misunderstood.
- Story states selection is not retained across pages and also includes confirmation when moving pages with selected items; expected state after returning to prior page is implied but not explicitly spelled beyond 'not retained across pages'.
- Post-import statement wording is grammatically unclear ("instead they are in greydout inside the catalog import page"); interpretation is imported rows should become disabled in import table.
- Toast duration/style should match existing Frame import pattern, but exact measurable duration value is not in this issue.

5. Risks
- Incorrect deduplication logic may hide valid distinct items or show duplicates if VW code normalization is inconsistent.
- Already-imported flag miscalculation can allow duplicate imports or wrongly disable selectable items.
- Race conditions during in-progress import may still allow selections/Add actions if UI disablement is not globally enforced.
- Selected count inaccuracies can occur with mixed disabled/selectable rows and header/footer select-all interactions.
- Pagination confirmation modal may fail to block navigation, causing silent selection loss.
- Incorrect default attributes on imported records (Status/Price) can create downstream pricing/activation issues.
- Mismatch between backend result totals and UI range/total display can break trust and selection expectations.
- Toast outcome may not reflect backend async completion state, especially on delayed failures.
