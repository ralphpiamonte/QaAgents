Issue: GEM-35731 (Story)

1. Jira issue summary
374. BE - Catalog Import - Spectacle Lens Add-Ons Product Category and Filters (Category, Add-On Name)

2. Requirement/bug analysis
- Story scope is backend for Catalog Import support of a new Product Category option: "Spectacle Lens - Add-Ons".
- Availability rule stated: Spectacle Lens category in catalog import is available only for non-PV organizations, and catalog import is not available for PV organizations for other categories as well. This implies this new category should also follow non-PV-only availability constraints.
- When "Spectacle Lens - Add-Ons" is selected, add-on-specific filters must be shown and used for search/import flow.
- Filter definitions include Supplier, Category, and Add-On Name with explicit UI behaviors documented (searchable fields, select behavior, sorting/defaults, clear behavior). Although this is BE story, FE-linked stories indicate contract/API behavior must support these constraints consistently.
- Supplier filter is described as searchable single select DDM infinite scroll, with values: default "All" first, then active loaded supplier locations sorted A-Z; if none loaded then only "All".
- Supplier sourcing rule: loaded eyeglasses active supplier locations across organization locations regardless of currently selected context location; electronic supplier locations only.
- Supplier selection behavior for retrieval: All => master catalog; selected loaded suppliers => corresponding supplier catalogs.
- Category filter is multi-select infinite scroll with values Coatings, Finishing, Other, Surfacing, Tints sorted A-Z.
- Add-On Name filter is searchable text with max 200 characters and no minimum characters in main description; comments introduce possible 1-character typeahead behavior for search bar.
- Multi-select behavior requirement applies to multi-select filters: keep dropdown open while selecting, explicit outside click to close, one in-field X clears all selected values, individual deselection only via dropdown.
- Applied filters must display as text list within search bar, with ellipsis truncation when too long.
- Actions: Search executes using current search value and filters and populates Search Results; selected criteria persist after Search. Clear Filters resets search bar, all filter fields, and search results table.
- Linked stories GEM-35732/GEM-37159 contain downstream search results/selection/add behavior, so this story must at minimum return data/filtering compatible with those flows.
- Comment history indicates prior conflict around Supplier single vs multi-select; latest description still states single select, so unresolved ambiguity must be clarified before final validation.
