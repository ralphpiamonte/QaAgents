Issue: GEM-37158 (Story)

1. Jira issue summary
4. FE - Catalog Import - Spectacle Lens Add-Ons Product Category and Filters (Category, Add-On Name)

2. Requirement/bug analysis
- Story scope is FE behavior in Settings > Ordering > Catalog Import to support a new Product Category option: Spectacle Lens - Add-Ons.
- Product category availability is constrained by organization type: Spectacle Lens category is for non-PV organizations; catalog import is not available for PV organizations across categories.
- Spectacle Lens and Spectacle Lens Add-Ons are separate data structures and must be searched/imported separately.
- When Spectacle Lens - Add-Ons is selected, add-on-specific filters must be shown.
- Specified filters for this category are Supplier, Category, and Add-On Name.
- Supplier filter is defined in base description as searchable single-select DDM with infinite scroll, default value All, alphabetical sorting for supplier names, and sourcing from active loaded electronic supplier locations; includes behavior when no suppliers are loaded (All only).
- Comment discussion introduces conflict about Supplier possibly being multi-select; latest comment says unresolved and asks for decision, so final requirement is not confirmed.
- Category filter is multi-select DDM with infinite scroll and values Coatings, Finishing, Other, Surfacing, Tints sorted alphabetically.
- Add-On Name filter is searchable text field supporting alphanumeric and special characters with max 200 characters and no minimum characters.
- Comment indicates typeahead suggestions should appear under search input beginning at 1 character, but search results table is populated only when Search button is clicked.
- Multi-select behavior requirements apply to multi-select filters: selected values persist, dropdown stays open during selection, closes only on outside click, single internal x clears all selections, individual removal done by deselecting in dropdown, and deselecting one does not clear others.
- Applied filters are shown as text list inside search bar field and truncated with ellipsis when too long.
- Actions: Search executes using current search value + selected filters and populates Search Results; selected criteria remain after Search. Clear Filters resets search bar, all filters, and Search Results table.

4. Ambiguities
- Description says Add-On Name has no minimum characters, while comment states one character to start dropdown suggestions.
- Description lists both category and add-on name search fields; comment suggests removing dual search and relying on Add-On Name/Supplier/Category filters.
- Supplier selection behavior is contradictory: documented single-select vs open debate on multi-select in review comment.
- Applied filter display is stated as inside search bar field, but if dual search is removed, target UI element for applied list is unclear.
- Supplier dependency text references loaded eyeglasses supplier locations; applicability for add-ons may be inferred but not explicitly restated.

5. Risks
- Incorrect org gating could expose catalog import to PV organizations or hide it from eligible non-PV organizations.
- Supplier filter implementation mismatch (single vs multi) can break expected backend query behavior and user workflows.
- Typeahead triggering and Search button execution may conflict, causing premature table updates or stale results.
- Large supplier lists with infinite scroll may cause performance issues, duplicate entries, or ordering defects.
- Clear Filters may fail to reset results table or hidden stateful controls, leading to false user assumptions.
- Ellipsis truncation for applied filters may hide critical selection context and create usability issues.
- Special-character handling in Add-On Name may cause escaping issues or failed queries.
