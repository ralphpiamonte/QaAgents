Issue: GEM-36014 (Bug)

1. Jira issue summary
STG investigation of high-frequency 400 Bad Request errors for OrderDiscount and Ledger API calls in DD Dashboard, with root causes linked to misconfigured automation tests, invalid test data, and calls to a removed Ledger endpoint; latest comment states automation tests were updated and issue resolved.

2. Requirement/bug analysis
- This is a bug/investigation issue focused on abnormal 400 error volume observed in Datadog for OrderDiscount and Ledger-related API traffic in STG.
- Identified root cause for OrderDiscount 400s: requests used invoices whose invoice lines were all deleted, which produces Bad Request responses.
- Identified contributing cause: automation tests were misconfigured during/around test migration and generated many invalid OrderDiscount requests.
- Additional root cause identified in comments: high-frequency calls to a removed Ledger endpoint (/Ledger/invoice/{id}/...) that should no longer be called.
- Additional data-quality issue identified: Invoice endpoint calls used invalid locationId/patientId values (BillingTransaction IDs instead of Uprise IDs), likely causing request failures/noise.
- Comment trail indicates remediation was performed ('automation test is updated and this issue is resolved'), so QA focus should verify post-fix behavior and absence of recurrence.
- Given issue context, expected behavior is reduction/elimination of avoidable 400s from automation-generated invalid inputs and no calls to removed endpoints.
- No explicit acceptance criteria, thresholds, time windows, or ownership boundaries are documented in the ticket.
